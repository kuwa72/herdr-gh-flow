# RFC: 競合・類似ツールの調査（Herdrエコシステム・gh extension・AIエージェント連携CLI）

- **ステータス**: Proposal / RFC
- **作成日**: 2026-09-06

---

## 1. 調査の目的と背景

`herdr-gh-flow`（`hgf`）は、**GitHub Issue駆動開発 × TDD規約 × Herdr（マルチペイン/セッション管理） × マルチコーディングエージェント連携**をシームレスに結合する開発体験の提供を目指している。

本調査では、親課題 [#16](https://github.com/kuwa72/herdr-gh-flow/issues/16) における「提供形態（単体CLI vs Herdrプラグイン vs ハイブリッド）」および「UX設計（TUI/インライン/マルチペイン）」の意思決定に先行するインプットとして、3つのレイヤーから既存エコシステムと先行事例を調査・分析した。

1. **Herdr エコシステム**: 既存プラグイン・インテグレーションおよびセッション管理の現状
2. **GitHub CLI (`gh`) エコシステム**: `gh extension` における Issue/PR/ダッシュボード/ブランチ管理のUX
3. **AIエージェント駆動開発支援CLI**: Aider, Claude Code, Cline, Devin等の連携ツール・ワークフロー自動化

---

## 2. カテゴリ別 類似・先行ツールの調査

### 2.1 Herdr エコシステム

| 対象 | 概要・機能 | hgf との関連性・示唆 |
| :--- | :--- | :--- |
| **Herdr Integrations (`herdr integration`)** | `claude`, `devin`, `antigravity-cli`, `codex`, `opencode`, `copilot` などのシェル環境・通知・状態監視フックを管理 | Herdrは各エージェントのライフサイクル状態（`idle`, `working`, `blocked`, `done`）を検知可能。ただし「GitHub Issueからタスクを拾ってエージェントを立ち上げる」上位ワークフロー層は提供されていない。 |
| **Herdr API / CLI (`herdr pane`, `agent`, `worktree`)** | ソケット経由でペイン分割（`pane split`）、テキスト送信（`pane send-text`）、worktree連携を提供 | `hgf` はHerdrを低レイヤのマルチプレクサ基盤として活用し、開発フローのオーケストレーションに特化するのが最も相性が良い。 |

> **現状**: Herdr単体ではIssue連携やTDD規約の強制機能は持たない。そのため、`hgf` はHerdrエコシステムにおける「実践的ワークフロー拡張（オーケストレーター）」として独自の存在価値を持つ。

---

### 2.2 GitHub CLI (`gh`) エコシステム

GitHub CLIの拡張機能（`gh extension`）では、多くのTUIや個別タスク支援ツールが存在する。

| ツール | 種別・UX | 特徴 | 課題・hgfとの違い |
| :--- | :--- | :--- | :--- |
| **`gh-dash`** (dlvhdr) | TUI (Bubble Tea) | PR・Issue・Notificationを一覧ダッシュボードで閲覧・キー操作 | 閲覧・ステータス確認が主目的。特定Issueに対するブランチ作成やエージェント起動といった「着手・作業実行」へのブリッジがない。 |
| **`gh-poi`** (seachicken) | CLI / TUI (fzf) | マージ済みローカルブランチの安全な一括クリーンアップ | ブランチ整理に特化。開発着手〜PRライフサイクルの支援ではない。 |
| **`gh-i`** (gennaro-tedesco) | CLI / fzf | インタラクティブなIssue検索・閲覧 | 単なるIssueブラウザにとどまり、エージェントやプロンプト生成との連携はない。 |
| **`gh-sherpa`** (InditexTech) | CLI | Jira / GitHub Issueからのブランチ作成・PRテンプレート自動作成 | ブランチ命名やPRの標準化を行うが、AIエージェントやターミナルマルチプレクサとの統合はない。 |

> **示唆**: `gh extension` の配布・実行形態（`gh <name>` 形式、Go/バイナリやスクリプト）はユーザーにとって導入ハードルが極めて低い。`hgf` を `gh hgf` や `gh flow` としても呼び出せる設計にしておく価値は高い。

---

### 2.3 AIエージェント駆動開発支援CLI / ワークフロー自動化

| ツール / アプローチ | 特徴 | 長所 | 課題・hgfとの違い |
| :--- | :--- | :--- | :--- |
| **Claude Code / Aider** | インラインCLI型コーディングエージェント | 高い実装能力、Gitコンテキスト把握 | エージェント単体では「どのIssueから着手するか」「TDDを遵守させるプロンプト成形」「CI監視・自動マージ」は人間の手動作業。 |
| **Devin / SWE-bench系 自律実行フレームワーク** | Issueやプロンプトを投げて放置でPR作成 | 完全自動 | 途中経過の可視性が低く暴走時のトークン消費大。人間の即時介入（ペアプロ感）が困難。 |
| **Copilot Workspace** | Web UIベースのIssue→仕様→実装→PR | GitHub統合が美麗 | ローカル環境（ローカルDB、カスタムスクリプト、ローカルテスト）の実行や外部エージェント（agy, Claude等）の切替が不可。 |
| **tmux + fzf + gh 自作スクリプト群** | シェル職人が各々作成する端末分割連携 | 自由度が高い | tmuxはエージェントの生死・状態（承認待ち/完了）を判別できない。共有・保守が困難。 |

## 4. `herdr-gh-flow` (`hgf`) のコアバリューと差別化要素

1. **エージェント非依存（Agent-Agnostic）なオーケストレーション**:
   - `agy`, `claude`, `devin`, `codex`, `opencode` など、プロジェクトやタスクの重さに応じて最適なエージェントを1キーで選択・起動可能。
   - 単一エージェントツールの制約（レート制限、特定モデルの不得意分野）を回避。
2. **厳格な規約の自動注入（TDD & Auto-merge ガードレール）**:
   - Issue内容を動的にパースし、`Red → Green → ci-wait → Auto-merge` の必須開発フローをプロンプトとして成形。エージェントが暴走して直接PRを作ったりテストを省いたりするのを防止。
3. **Herdrとの緊密な連携（マルチペイン & 将来的なライフサイクル検知）**:
   - メイン作業シェルを残したまま右側にエージェントペインを自動分割生成。
   - プロンプトを事前入力状態にし、ユーザーが最終確認して `[Enter]` で開始できる「人間主導の自律開発」UX。
4. **環境適応型ハイブリッド設計（Graceful Degradation）**:
   - Herdr環境（`HERDR_ENV=1`）ではペイン分割・リッチセッション連携を提供。
   - Herdr外（通常の端末、SSH、CI等）でも単体CLIとしてインライン起動し、Issue取得・ブランチ作成・プロンプト成形・`ci-wait` を提供可能。

## 5. 親Issue #16 へのインプット提示

### 5.1 提供形態の推奨案
- **「ハイブリッド型（単体CLI + Herdr検出）」を確定方針として推奨**:
  - コアバイナリ（またはコマンド）は `hgf` 単体で動作。
  - `HERDR_ENV=1` が有効な場合は自動で `herdr pane split` などのマルチペイン機能を発動。
  - さらに、シンボリックリンクやラッパーにより `gh hgf` / `gh flow`（gh extension）としても利用可能なインターフェース設計にしておくことで、GitHub CLIユーザー層への配布・導線を確保できる（#26 配布設計へ接続）。

### 5.2 基本UXモデルの推奨案
- **Issue選択〜作業開始**:
  - `fzf` ベース（または後続 #22 でGo/Rust化する際のBubble Tea/Ratatui等のTUI）による高速インクリメンタルサーチ + 右ペインプレビュー。
  - 1アクション起動（`[Enter]` で標準agy、キーコンビネーションで特定エージェントやworktree起動）。
- **エージェント実行モード**:
  - **Herdr内**: 右ペインにプロンプト入力状態で待機（レビュー＆実行）。左ペインは人間の操作（Git操作・ログ監視）として温存。
  - **Herdr外**: カレントターミナル内でエージェントをインライン直接起動（フォールバック）。

---

## 6. まとめ・次のステップ

本調査により、`hgf` は既存の「Issue閲覧TUI」や「特定エージェント専用CLI」のいずれとも重複せず、**『ローカルTDD開発規約 × マルチエージェント × ターミナルマルチプレクサ』を繋ぐ接着剤（Glue/Orchestrator）**としての独自ポジションが明確になった。

この結果をもって、親Issue [#16](https://github.com/kuwa72/herdr-gh-flow/issues/16) の提供形態およびUX基本方針の決定に進むことを推奨する。
